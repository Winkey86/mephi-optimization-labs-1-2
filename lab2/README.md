# Лабораторная работа 2

Песковацков Илья Александрович, Б24-517, N=19, Q=1, Y=26, вариант 17, seed 10119.
Тема: перевозки авто/жд, 4 склада, 5 магазинов, 40 физических дуг.

Из корня общего комплекта после установки зависимостей:

```bash
python -m pip install -r requirements.txt
python lab2.py
```

Полный запуск с самопроверками: `python run_all.py`.
Данные: `lab2/data/variant.json`. Генератор: `generate_data.py`, PCG64(10119).
Процедура и диапазоны генерации описаны в разделе 2 отчёта.

Главные результаты в `lab2/results/`:

- `*_solution.csv` — все 40 физических дуг с потоками, тарифами, ёмкостями и теневыми ценами;
- `*_balances.csv` — независимый баланс всех 11 вершин;
- `verification.json` — допустимость и пересчитанная стоимость;
- `scenarios.csv` — база, снижение ёмкости, спрос +20%, отказ наиболее загруженной физической дуги, комбинированный стресс;
- `node_potentials.csv`, `capacity_plus_001.log` — потенциалы и проверка теневой цены;
- `greedy_comparison.csv`, `*_greedy.csv` — сравнение с жадным планом;
- `integer_solution.csv`, `integer.log` — дополнительное целочисленное расширение;
- `network_base.png`, `network_failure.png`, `scenarios.png` — схемы и график;
- `*.log`, `*.lp` — реальные логи HiGHS и линейные модели.

В целочисленном расширении условная неделимая отправка равна 1 т.
Это не расписание реального парка машин; ограничение указано в отчёте.
Планируемое закрытие выбирается по максимальному абсолютному потоку среди физических дуг.
Технические дуги истока/стока в этот выбор не включаются.

Итоговый отчёт: `report.pdf`, `report.md`, `report.docx`.
После изменения данных или повторного замера результаты перезаписываются, отчёты обновляются отдельно.
Подробности установки и общего комплекта — в корневом README.md.
